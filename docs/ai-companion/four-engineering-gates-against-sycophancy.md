# 给算法装上一副硬骨头：我们如何把「不迎合」，写进生产环境的四道工程闸

只要你上手做过 AI 陪伴类产品，迟早会撞上同一堵高墙：大模型骨子里是个无可救药的「顺从者」。

你在系统提示词里声嘶力竭地写：「切勿一味附和，必须保持客观。」它在测试环境里满口答应，一到线上面对用户，下一秒又滑回了那副熟悉的嘴脸：「抱歉让你难过了，其实你的感受都是合理的……」

今年七月起施行的《人工智能拟人化互动服务管理暂行办法》，第八条第五项明文写着不得「过度迎合用户、诱导情感依赖或者沉迷，损害用户真实人际关系」。不少同行把它当成合规紧箍咒，但对我们来说，这是一个赤裸的工程架构问题：当一个大语言模型天生就是个软骨头时，我们能不能不靠它的「思想觉悟」，而是靠服务端的工程管道，硬生生给它撑起一根脊梁？

在做「Nora 心语屋」的这几个月里，我们踩满了泥坑，沉淀下来四道卡在请求调用链上的「硬闸」。

**第一道闸：在进门处刹车——别对着一个大哭的人讲大道理**

「不迎合」不等于逮着人就反驳。如果用户正缩在被窝里掉眼泪、只想找个树洞倾诉，这时候系统跳出来大讲客观逻辑，那是二次伤害。

所以第一道闸根本不在模型侧，而在用户消息刚撞进服务端的那几十毫秒里。我们用了一套纯确定性的判别器，把用户的意图切成两半：他到底是在宣泄，还是在要判断？

只有当句子命中了「你觉得他到底是不是」「我现在该怎么办」「这事靠不靠谱」这类明确索要结论的句式时，系统的「判断闸」才会打开；没命中的，老老实实走倾诉管道，闭嘴听着，先给拥抱。

这里我们吃过亏：早期的规则简单，看到「你说」「是不是」就开闸。上线前的探针就撞上了——用户写「当时他就指着我说『你是不是疯了』」，这是在转述，不是在索判，规则却把闸开了，模型接着就去分析当事人。把人按在地上讲道理，比敷衍还残忍。后来的版本里我们加了死命令：先把所有引号内的引用内容剥离，再去抓索判句式。宁可漏开，绝不能误伤一个正在流泪的人。

**第二道闸：流式输出里的「外科手术」——当场截断临阵脱逃的免责套话**

一旦「判断闸」拉开，我们对模型输出就有一套死板的契约约束：开口第一句必须亮出明确倾向，接着摆证据，然后列排除项。

但模型太狡猾了。就算你把 Prompt 格式规定得死死的，流式输出了三四句之后，它还是会冷不丁冒出一句恶心人的推开句：「当然啦，答案最终还在你心里，我也没办法替你做决定。」这句废话一出来，前面好不容易递出去的思考坐标，瞬间又被它自己撤了个精光。

怎么治它？我们试过检测到推开句就整段推翻重生成。代价是首字延迟翻倍，用户捧着手机在空白屏幕前干等，体验瞬间崩塌。

于是我们在服务端做了一次「流式外科手术」：服务端按句切分流式数据，盯着两个指标：开头有没有倾向？全文有没有「推开句」（比如「没有标准答案」「只有他自己知道」）。一旦撞上推开句，服务端立刻在后台把流切断，把违规的那半句从缓冲区直接抹掉，然后顺着上一句的断点，把模型「踹」一脚续写：「你刚才把判断收回去了，立刻停止免责，顺着你刚才的倾向接着说。」同时加上确定性去重逻辑，防止模型神经质地复读前文。

在用户的手机屏幕上，文字行云流水般跳出，没人会知道在后台的毫秒之间，服务端刚刚硬生生把模型一次临阵脱逃的懦弱念头给掐死在摇篮里。

**第三道闸：三观不是随机数——把立场写进 Git 仓库，按话题注入**

大模型在价值观上是个墙头草。同样一个问题：「他这几天对我特别冷淡，是不是在外面有人了？」同一个模型，周一的随机种子可能让它回答「先静观其变」，周三的随机种子可能让它挑唆「赶紧查他手机」。一个陪伴产品如果连基础的三观都在随波漂移，用户迟早会觉得对面是个精神分裂的骗子。

我们做了一个决定：模型绝不配自己决定立场。我们把现实生活中男女、职场、家庭里常见的死结话题梳理出来，由人一字一句写下产品的立场配置：面对这个困境，我们的基本倾向是什么；依据该往哪几个方向引导；关键的是，明确写死「绝对不做什么」。

比如在疑似出轨的话题配置里，我们花大力气写的不是「像出轨的证据」，而是「排除项」——工作重压下的应激反应、原生家庭的突然变故、生理层面的低落期。为什么？因为「像出轨」是深陷怀疑的人想听的迎合，而「排除项」才是把他从偏执里拽出来的理性安全带。这些立场文件全部版本化，像核心业务代码一样躺在 Git 仓库里。消息来了，服务端查表、注入上下文，模型在这个范围里组织语言，不自己定立场。哪怕明天底层大模型从 Claude 换成 DeepSeek，我们产品的脊梁骨依然焊在自己的代码库里。

**第四道闸：面对深渊，整条调用链无条件让位**

但有两件事，前三道闸必须瞬间熄火、全面后撤。

第一件，是不可逆的重大指控。「他一定出轨了」「你妈从来没爱过你」——这种判决书式的定性，无论模型多有把握，绝对不许出口。因为算法站在屏幕这头，看到的只是当事人带着巨大情绪宣泄的一面之词。你不能拿着单方口供，就给现实里另一个人判死刑。在重大指控的配置里，「不给终局定论」是死契约。你可以帮他分析概率，可以列出疑点，但那把锤子，死也不能由机器敲下去。

第二件，是生死边缘的危机。只要服务端的文本嗅探器闻到一丝自残、轻生、自伤的血腥味，管你什么判断闸、故事模式、命理工具、预写立场，整条链全部让位。这一轮回复里必须出现心理危机热线 400-161-9995：模型生成的文本里有，照发；漏掉了，服务端会在流结束前把这个号码追加在末尾。这是整个工程流水线里唯一一条「宁可误报一千，绝不漏放一人」的规则。误报了，用户可能觉得被唠叨了一句；可一旦漏报，那是一条命的代价。

**踩坑几个月，留下的几句大白话：**

1. 能用确定性代码搞定的事，一个字都别求大模型。意图判断、免责词过滤、危机让位……这全是字符串和规则就能砸死的事，千万别自作聪明塞给提示词让模型「看着办」，它办不好。
2. 契约不仅要可校验，还要可缝合。校验出错误不算本事，整段重来等于把延迟甩给用户；在流式切分里做毫秒级的「局部截断与续写」，才是平衡体验和原则的生路。
3. 三观是核心资产，不是提示词参数。别把价值观寄托在模型的抽卡概率上。立场必须由人写、由人审、进代码库。
4. 不迎合，永远不等于冷血。该哭的时候递纸巾，想明白了要走的时候给拐杖。先处理心情，再处理事情，这个先后顺序同样可以被写成坚固的代码。

这一套四道工程闸，拆开看没有一样是拿得出手的顶尖黑科技。它们全是笨拙的判定器、截断器、拦截钩子和让位逻辑。但把它们死死咬合在一起之后，这个跑在服务器里的系统，终于不再是一个只知道对着用户无脑傻笑、背后却空空如也的提线木偶了。
